# XNU loader boot menu

The UEFI loader (`uefi/XnuLoader`) shows a menu before starting XNU.

The screen is drawn large, in English, by `BootMenuDraw.c` into a buffer, then copied to the screen by the GOP
(`Blt`). Without a GOP or without memory for the buffer, the menu falls back to the firmware's text console.
Layout designed for the S10 panel (1440 × 3040); on another screen, the drawing is only cropped.

Font: Spleen 32x64 and 16x32 by Frederic Cambus, BSD-2-Clause license, commit `cfde412`
(https://github.com/fcambus/spleen). The `FontSpleen*.h` headers are generated by `tools/bdf2c.py` and
reproduce the license notice.

| Key | Effect |
|---|---|
| Volume + / Volume − | move up / down in the menu |
| Power (short press, on release) | confirm |
| Bixby | stop the countdown |
| Volume − held at startup | menu without countdown |
| Volume + held at startup | menu, cursor on "recovery" (still needs confirming with Power) |

Entries:

1. **Boot iOS** (start iOS), selected automatically after 5 s with no key press. Build option: `-D B2L_MENU_TIMEOUT_S=n`; 0 means no automatic start.
2. **Stay here** (do not start): the phone waits, without a watchdog. A key press returns to the menu.
3. **Reboot to recovery**: writes `INFORM3 = 0x12345674` and `SYSIP_DAT0 = 0xFF` into the PMU (`0x15860000`), then requests a reset. These are the values of the Samsung exynos9820 kernel (`drivers/samsung/sec_reboot.c`, `drivers/soc/samsung/exynos-reboot.c`). **Not yet tested on the phone.**
4. **Reboot**: like the Samsung kernel (`exynos-reboot.c`), `RST_STAT = 0` then `SWRESET (0x3A00) = 1 << 1` in the PMU; `ResetSystem(EfiResetCold)` as a fallback. The Silicium firmware reset writes `1` (the 9810 value) and does nothing on the S10 (seen in B1L-0216).

## Guarantees

- **Failure before UEFI boot services are exited** (kernel not found or invalid, memory, video, final memory map): messages stay on screen until a key is pressed. The menu then returns without a countdown, so a broken kernel is never relaunched in a loop.
- **Failure after UEFI boot services are exited**: only the progress bar can still show anything. Red square 0 = memory map refused, red square 1 = exit refused. The processor stops; hold Power to restart.
- **Remembered option**: this is a UEFI variable that only places the cursor. The countdown always starts iOS, so a remembered "reboot" cannot loop. On this firmware the variables live in RAM (`PcdEmuVariableNvModeEnable=TRUE`): the choice survives a return to the menu, not a restart.
- **No partition writes.**
- **Without keyboard or console**, the loader starts directly, as before.

## Tests

- `tests/boot_menu_test.c` (run by `scripts/test-loader.sh`): countdown, navigation, confirmation, debounce, forced boots.
- `tests/boot_menu_draw_test.c`: drawing within bounds (guard after the last line, intact line margin, small screen). With a file name as argument, it writes the screen as PPM so it can be viewed.
- EFI build: `scripts/build-efi.sh`, in a copy of the EDK2 workspace (`cp -c -R` of a `mu-work-*`), so the EFI used by `b1l-build.sh` is not touched.
