# ios-b1lte

**iOS 26 on the Samsung Galaxy S10 (`beyond1lte`, SM-G973F, Exynos 9820)**

Apple's open-source XNU kernel running on the Galaxy S10, booting the **unmodified iOS 26 userland** (launchd, system daemons, backboardd and SpringBoard) from the phone's own UFS storage, with touch input, Wi-Fi, an in-kernel emulator for the arm64e instructions the ARMv8.2 cores lack, and a Metal driver for the Mali-G76 GPU in progress.

> [!WARNING]
> This is an experimental community porting and research project, not a product. Apple's security policies (AMFI, code signing enforcement, the Secure Enclave) are relaxed for hardware bring-up. Installing the iOS root volume overwrites Android's `userdata` partition and **erases all user data**. A wrong partition write can brick the phone: read [docs/installation.md](docs/installation.md) first.

## Hardware Architecture

| Component | Hardware on the Galaxy S10 (`beyond1lte`) | Port Driver & Subsystem |
| --- | --- | --- |
| **SoC** | Samsung Exynos 9820 (8 nm) | Board layer `B2LPlatformExpert`, Apple device tree generated by `XnuLoader` |
| **CPU** | 8 cores in three clusters: 2x Mongoose M4, 2x Cortex-A75, 4x Cortex-A55 (ARMv8.2-A) | PSCI SMP bring-up, GIC interrupts, cluster-aware placement, arm64e instructions (PAC, JSCVT, RCPC…) emulated in the kernel |
| **GPU** | ARM Mali-G76 MP12 | `B2LMaliService` / `b2l_mali_core` kernel driver (from HakiOS) + Mesa panfrost/Bifrost compiler + Metal driver (`userspace/metal`) |
| **Display** | 6.1" Dynamic AMOLED, 3040 × 1440, panel s6e3ha9 | `B2LFramebuffer` over the UEFI GOP framebuffer (DECON-F) |
| **Touchscreen** | Samsung `sec_ts` Y771 on `hsi2c@104B0000` | `B2LInput` HID digitizer |
| **Audio** | Exynos ABOX + 2x Cirrus Logic CS35L40 amplifiers | Kernel tone path (parked); HakiOS AudioServerPlugIn in `userspace/audio-plugin` |
| **Wi-Fi** | Broadcom BCM4375 | `B2LWifi` + `apple80211` bridge for `wifid` |
| **Bluetooth** | Broadcom BCM4375 (UART HCI) | `B2LBluetooth` firmware loader (parked) |
| **Storage** | UFS | Native UFS transport, HFS+ root on `userdata`, SYSTEM partition for the native cache |
| **Memory** | 8 GB (~7.1 GB visible) | Fixed RAM bank list (`b2l_ram_ranges.h`) |
| **Boot Chain** | Samsung S-Boot (bootloader unlocked) | [beyond2lte UEFI](https://github.com/orhunnx/beyond2lte-uefi) (Project Mu) → `XnuLoader` boot menu → XNU |

## Boot Methods

### Method 1: BOOT partition image (current)
`scripts/package-boot.py` packs the UEFI firmware, its embedded `XnuLoader` and the XNU kernel into an Android boot image that S-Boot loads from the `boot` partition (`tools/b1l/b1l-build.sh`, stage `package`, writes `out/b1l-metal-NNNN/boot.img`).

`XnuLoader` builds the Apple device tree, shows a boot menu ([docs/boot-menu.md](docs/boot-menu.md)), exits boot services and jumps into XNU. If XNU fails to start, the menu comes back.

## Getting Started

### 1. Prerequisites
- Galaxy S10 **SM-G973F** (`beyond1lte`) with an unlocked bootloader and TWRP (root ADB).
- A Mac with Xcode and the iOS 26.5 **Kernel Debug Kit** (KDK 25F71); see [docs/build.md](docs/build.md).
- Android platform tools (`adb`), Python 3 and `llvm-mc` (paths in [.env.example](.env.example)).
- The iOS 26 IPSW **23G90** (iPhone 16 Pro Max), which is never redistributed.
- A full partition backup made with `tools/flash-kit/backup-partitions.sh`.

### 2. Extract Device Firmware Blobs
Wi-Fi/Bluetooth firmware, NVRAM and calibration data come from your own phone and are never committed (`.gitignore` blocks them):

```bash
# Phone in TWRP with root ADB
tools/flash-kit/check-device.sh
# TODO: list the commands that copy the BCM4375 firmware and NVRAM into $S10_PORT/device-s10/wifi-bt-fw/system
```

### 3. Prepare XNU and the Device Tree
```bash
scripts/fetch-xnu.sh     # pinned Apple XNU source
scripts/prepare-xnu.sh   # applies patches/ and copies xnu-overlay/ into the tree
scripts/build-efi.sh     # XnuLoader (it generates the Apple device tree at boot)
```

### 4. Build the iOS Root Image
```bash
tools/b1l/build-ios-root.sh      # HFS+ USERDATA image from the 23G90 IPSW
tools/b1l/build-system-image.sh  # SYSTEM image with the translated native cache
```

### 5. Pack, Flash & Boot
```bash
cp .env.example .env    # adjust, then export the variables
bash tools/b1l/b1l-build.sh 0001 b2l-metal-v1   # kernel → package → SYSTEM → BOOT, every write read back
bash tools/b1l/watch-build.sh                     # live progress of each stage
```

Only BOOT (`sda14`), SYSTEM (`sda25`) and USERDATA (`sda34`) are ever written; see [tools/flash-kit/docs/partition-map.md](tools/flash-kit/docs/partition-map.md). Day-to-day usage and recovery steps are in [docs/build.md](docs/build.md) and [docs/troubleshooting.md](docs/troubleshooting.md).

## Repository Structure

```
├── common/                 # Code shared by the loader and the kernel (SMP, memory)
├── docs/                   # Architecture, build, installation, troubleshooting, design notes
│   ├── journal/            # Build-by-build reports and screenshots
│   ├── plans/              # Early plans (port, GPU)
│   └── projet/             # Project documentation (French)
├── patches/                # Patch series applied on Apple open-source XNU
├── scripts/                # Kernel, EFI and Mesa/Metal builds, packaging, log pullers, host tests
├── tests/                  # Host tests (C and Python): loader, Mach-O, arm64e, packaging
├── tools/
│   ├── b1l/                # Build/flash loop: b1l-build.sh, delta flashing, watchers, dyld cache tools
│   ├── flash-kit/          # Device checks, partition backup and guarded flashing
│   └── scan-isa.py         # Counts post-ARMv8.2 instructions in the dyld cache
├── uefi/                   # XnuLoader (boot menu, device tree, Spleen font) and BootSurvey
├── userspace/              # iOS-side libraries built for arm64
│   ├── metal/              # Metal driver for the Mali-G76 (from Scion / HakiOS)
│   ├── mesa/               # Mesa panfrost glue (AIR → NIR, DRM shim)
│   └── audio-plugin/       # HakiOS AudioServerPlugIn
└── xnu-overlay/            # Board drivers and files copied over the XNU tree
```
